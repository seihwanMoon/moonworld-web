## 페이지별 구성

### Home `/`

1. Hero에서 제조업 업무 이해와 AI 적용을 한 문장으로 전달한다.
2. Manufacturing DX, Industrial AI, Generative AI & Agents, Engineering AI를 소개한다.
3. 생산·설비·품질·사내 지식 검색·CATIA 설계 변경을 적용 검토 시나리오로 제시한다. 실제 납품 사례라고 표현하지 않는다.
4. 공개 가능한 프로젝트 상세 자료를 준비 중임을 밝히고, 확인되지 않은 성과·고객 로고를 비워 둔다.
5. CATIA Engineering Agent는 개발·내부 검증 상태, 지식관리 시스템은 기획·연구 후보로 구분한다.
6. 현황 분석 → 기술 검토 → PoC/설계 → 구축 → 적용 및 개선 절차를 안내한다.
7. 프로젝트 문의 CTA로 연결하고 Contact 페이지에서 공식 이메일 문의 주소를 안내한다.

### Solutions `/solutions/`

각 분야별로 **고객 문제 → 적용 기술 → 제공 기능 → 기대 효과 → 수행 방식** 순서로 설명한다.

- 제조 DX: 생산·설비·품질 정보 단절, 현장 업무 디지털화와 기존 시스템 연계.
- Industrial AI: 활용 가능한 데이터 검토, ML/DL 분석·예측, 결과를 기존 업무 흐름에 전달.
- Generative AI & Agents: 업무 문서·사내 지식 검색, 승인 가능한 업무 자동화, 기존 시스템 연계.
- Engineering AI: CATIA V5 기존 모델에서 확인 가능한 정보와 변경 가능 후보를 살펴보고 승인된 한정 경로를 실행·확인하는 방향.

효과는 정성적으로 설명한다. “품질 예측·이상 탐지·예지보전·비전 검사”는 적용 가능한 사례 유형으로만 표기한다.

### Experience `/experience/`

제조 정보시스템 구축, 스마트공장 구축·고도화, ML/DL/LLM 소프트웨어 개발, CATIA·설계 자동화 경험을 직접 소개한다. 역량 영역과 제공 가능한 범위를 설명하고, 고객명이나 성과 수치가 근거로 확인되지 않으면 개별 프로젝트 사례로 꾸미지 않는다. 공개 승인된 사례는 프로젝트 분야, 고객 산업, 문제, 수행 범위, 기술, 결과물, 성과 근거를 확인한 뒤 추가한다.

사례 게시 필드: 프로젝트 분야, 고객 산업, 문제, 수행 범위, 기술, 결과물, 검증 가능한 성과, 공개 승인 범위. 각 사례는 고객 승인·소유권·익명화 여부를 확인한 후 구조화 데이터로 추가한다.

## SEO 콘텐츠

- 페이지별 한국어 title/description과 canonical URL을 설정한다.
- Open Graph title, description, type, url, site name, locale를 제공한다.
- 공개하지 않는 고객명·실적·제품 성능을 메타 설명이나 구조화 데이터에도 넣지 않는다.
- `/sitemap.xml`은 공개 페이지 경로만 포함하고 `/robots.txt`에서 사이트맵을 가리킨다.
